# Updating the catalog

Run only after an explicit catalog-update request. Update this skill's references, not the current project or other installed skills. Keep English prose and bilingual search aliases.

1. Read the source and coverage notes for the requested libraries, or all libraries for a full update. Inspect official navigation, public registries, `llms.txt` and sitemaps where available. Prefer machine-readable indexes, but compare them: prompt-kit's navigation and beUI's registry have contained entries absent from `llms.txt`.
2. Reconcile public component identities against existing JSONL records. Use registry IDs when available. Preserve named variants sharing a gallery URL, including Fluid Base UI variants and Planes gallery items. Deduplicate repeated bookmarks rather than dropping distinct components with the same name in different libraries.
3. For each entry preserve `name`, `section`, an English `description`, behavior-oriented `tags`, `synonyms_ru`, `synonyms_en`, `url`, `source` and `evidence`. Optional `registry_id` identifies registry variants; `kind: family` or `kind: category` prevents confusing a collection with a single component. Each JSONL line must be a complete JSON object.
4. Treat tags as search hints. Do not infer live behavior from a name alone or mark a component free merely because its demo is public. Keep public, paid and unverified source access distinct. Do not obtain closed source during indexing. When new evidence supersedes a claim, update its note and date; retain unverified status for untouched behaviors.
5. Record the verification date, authoritative index URLs, counts, missing/unavailable sections, and whether coverage counts individual components, variants, families or categories. If a site is down, keep previous records with their old date and record the failure; do not erase them or claim current completeness. Do not use advertising totals as verified inventory counts.
6. Keep 21st as categories and task-specific search, never an exhaustive component inventory. Keep Libraries.dev as a map of its libraries, without recursively indexing their packages. Preserve the favorite component links in `index.md`; exclude private chats and browser/account information.
7. Validate JSONL parsing, required fields, duplicate identities, local reference paths and consistency of counts. Compare entries against each official inventory, explicitly accounting for documentation-only and category pages. Run the search helper against code changes, task steps, a toggle, a no-match phrase and a paid candidate. Check the skill with the locally available `skill-creator` validator if present; do not install tooling just to search.

Report added/removed/changed entries, coverage gaps and stale sources. No scheduled synchronization is part of this skill.
